# 2026-10-30 作業記録：KIT-SEC-005 回答履歴に容量・件数・保存回数の上限がない（森下担当）

ブランチ: `fix/sec-005-answer-history-quota`（`main` の `8091710` から作成）

## 指摘（Codex の調査、Medium）

回答の各版は最大256KiBに制限されているが、アカウント単位の版の数・合計容量・保存回数に上限がなかった。1アカウントで版を足し続けて、DB を埋められた。

## 確認したこと

- 修正前は、256KiB の回答を25版保存すると全25版（約6.5MB）が残り、保存回数の上限もなかった。
- 古い版を読む API はない（`GET /api/v1/answers/current` は最新版だけ）。画面・家族共有・QR共有も最新版だけを使う。
- `SharedSnapshot`（既存のモデル）は、元の版を外部キーで参照する。

## 対応

- 回答の保存に、アカウント単位の回数制限を追加した（`answer_save`、1時間60回）。保存回数の加算・新しい版の追加・古い版の削除を、同じトランザクションでコミットする。競合で失敗した保存は数えない。
- 残す版を最新の20版までにした（`ANSWER_HISTORY_KEEP`、合計は最大約5MiB）。それより古い版は、保存と同じトランザクションで削除する。`SharedSnapshot` から参照されている版は残す。
- 同時の保存で版が重なったときの一意制約の違反を、古い版を消す前に明示的に書き込んで確かめ、409 `revision_conflict` にした（自動の書き込みで例外が漏れないように）。

## 判断が必要な点

- 古い版を削除するのは、元に戻せない変更。古い版を読む機能は今はないが、将来「回答の履歴を見る」機能を作る場合は、残す版の数（`ANSWER_HISTORY_KEEP`）を見直す。
- 上限の値（1時間60回、20版）は仮の値。`config.py` で変えられる。

## 検証

- `tests/test_answer_history_quota.py` を追加した（5件）。確認したのは、最大サイズで25版保存しても最新20版だけが残ること、保存回数の上限、競合した保存を数えないこと、共有の元の版を残すこと、8件同時の保存で1件だけ成功し回数も1回だけ数えること。修正前は3件失敗し、修正後は5回繰り返してすべて成功した。
- pytest 189件すべて成功。

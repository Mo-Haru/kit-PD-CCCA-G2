## 1. 共有画面：期限を選んでも「共有する内容を確認」を押せないことがある

### 症状

共有画面（`/sharing`）で、共有する範囲を選んだあとに有効期限を選んでも、「共有する内容を確認」が押せないままになることがあった。

### 原因

- リンクの種類を「長期」に切り替えたとき、ボタンを押せるかの判定（`clearPreview()` → `controls()`）が、期限の既定値（3年後）を入れる処理（`visibility()`）より先に動いていた。期限が空の状態で判定するため、既定値が入ったあともボタンは押せないままだった。期限欄を触り直すまで直らない。
- 期限付きで、次のような期限のときは、ボタンが押せないだけで理由をどこにも表示していなかった。日付を選べる範囲も絞っていなかった。
  - 日付だけ入れて時刻が空（Chrome の `datetime-local` は、入力の途中だと `value` が空になり、`input` イベントも起きない）
  - 31日（長期は3年）を超える日時、または過去の日時

### 対応

- `app/static/js/watashi/sharing.mjs`
  - 範囲・種類を変えたときは、`visibility()` で期限の既定値を入れてから判定するように順番を入れ替えた。
  - ボタンを押せない理由を返す `previewBlocker()` を追加した。ボタンの下（`#preview-help`）に、範囲が未選択・期限が空・日付と時刻を入力中・期限が範囲外・暗号化を解除していない、のどれかを表示する。
  - 期限欄に、選べる範囲（`min`/`max`）を設定した（`expiryBounds()`）。下限は次の分、上限は最長期間を分単位に切り捨てた日時で、端の日時を選んでもサーバーの上限を超えない。画面を開いたままでも合うように、期限欄にフォーカスしたときに範囲を更新する。
  - 入力の途中でも理由の表示を更新するため、期限欄の `keyup`・`blur` でも判定し直すようにした。
- `app/templates/sharing/index.html`：理由を表示する `#preview-help` を追加し、ボタンの `aria-describedby` に指定した。

### 検証

- `tests/sharing_page.mjs` にテストを追加した。期限が空のまま長期へ切り替えたら、すぐにボタンを押せること。範囲が未選択・期限が範囲外・日付と時刻を入力中のときに理由を表示すること。`expiryBounds()` の端の日時が上限の確認を通ること。
  - 順番の入れ替えを元に戻すと、追加した長期のテストが失敗することを確かめた。
- Chrome（Playwright、API は偽の応答に差し替え）で実際の画面を操作し、次を確かめた。
  - 長期へ切り替えると、既定値の3年後が入り、すぐにボタンを押せる。
  - 期限付きで日付だけ入れると「日付と時刻を最後まで入力してください」と表示される。31日以内の日時を入れるとボタンを押せて、内容を確認できる。31日を超える日時では理由が表示される。
- pytest：208件成功、2件失敗（`tests/test_config.py::test_development_passkey_origin_without_dotenv` の2件）。失敗は作業前からの `config.py` の変更（`WEBAUTHN_ORIGIN` の既定値を `5001` に変更）によるもの。`config.py` を戻した状態では210件すべて成功した。
- 未確認：Safari・Firefox・スマートフォンでの期限の入力。実際のパスキーで解除してからの一連の流れ。
- メモ：この環境では `node` が PATH になく、LM Studio に同梱されている node（v25.5.0）を使ってテストを動かした。

## 4. 家族画面を一覧にし、共有を作る手順を別の画面（`/family/share`）に分ける

### 要望

- `/family` を開いたら、家族の一覧と「共有を開始」ボタンを出し、共有を作る画面とは分ける。共有されたものの一覧も出す。
- 「共有を開始」のあとは、ロック解除 → 共有内容の選択 → 共有する家族と期限の指定 → 共有内容の再確認 → 共有確定の順に進む。

### 対応

- `/family`（`app/templates/family/index.html`、`family.mjs`）
  - 並び順：家族（一覧、共有を開始）→ 自分が家族に共有したもの → 家族から共有されたもの → 家族を招待。
  - 共有を作るフォーム（範囲・家族・期限・確認・確定）を外した。「共有を開始」は `/family/share` へ進む。共有できる家族（登録中の家族）がいないとき、またはログインしていないときは押せず、理由を表示する。
  - 共有の詳細（モーダル）の「この範囲で更新」を、「内容を選び直して更新」に変え、`/family/share?update=<共有ID>` へ進むようにした（更新に必要だった範囲の選択と再確認が、この画面から無くなったため）。期限切れ・停止済みの共有には出さない。
- `/family/share`（新規：`app/templates/family/share.html`、`family-share.mjs`、`family-share-flow.mjs`、ルートは `protection_pages.family_share`）
  - 上に手順（1. ロック解除 / 2. 共有内容の選択 / 3. 家族と期限 / 4. 再確認）を出し、今の手順だけを表示する。「戻る」「次へ」で進む。確定すると「共有しました」の表示になる。
  - 「次へ」を押せない間は、その手順の条件（解除していない、範囲が空、家族がいない、期限が過去・入力の途中）を満たしていない。
  - 再確認では、そのときに読み直した回答・相手・鍵・期限・範囲を表示する。確定のときに、もう一度読み直して、確認した内容と同じかを確かめる。違えば（例：確認のあとに相手の鍵が変わった）共有せず、確認の手順へ戻す。
  - 本人確認の期限が切れたら、選んだ内容は残したまま、最初のロック解除に戻す。
  - 更新（`?update=`）では、相手と期限を変えないので「家族と期限」の手順を省く。
  - 確認と確定の判定（`confirmationStillMatches` など）は、`family.mjs` から `family-share-flow.mjs` へ移した（中身は変えていない）。
- `base.html`：`/family/share` でも、メニューの「家族」を現在地にした。パンくずは `意思の記録 › 家族に共有する`。
- 説明を直した：`README.md`、`docs/answer-demo.md`、`docs/morishita.md`。

### 検証

- `tests/family_share_page.mjs`（新規）：一連の流れ（解除 → 内容 → 家族と期限 → 再確認 → 確定）、期限が過去のときは進めないこと、戻ると確認が消えること、確認のあとに鍵が変わったら共有せず戻ること、共有されるのは選んだ回答だけであること、本人確認が切れたら最初に戻ること、未ログイン、更新の流れ、更新できない共有のときの扱い。
- `tests/family_rekey_page.mjs`：フォームを外したことに合わせて直し、「共有を開始」が `/family/share` へ進むこと、「内容を選び直して更新」が `?update=` 付きで進むことを足した。
- `tests/test_routes.py`、`tests/test_menu.py`、`tests/test_protection.py`：`/family` にフォームがないこと、`/family/share` の手順の並びと初期状態、パンくずなどを足した。
- Chrome で、`/family/share` を一通り操作し（API は偽の応答に差し替え）、手順の表示と、確定で送られる内容が選んだ質問だけであることを確かめた。未ログインの `/family` の表示も見た。
- pytest：222件成功、2件失敗（1. と同じ `tests/test_config.py` の2件で、作業前からの `config.py` の変更によるもの）。
- 未確認：実際のパスキーと実在の2アカウントでの、解除から共有確定、相手側での表示までの一連の流れ。更新の流れは、実際のブラウザでは操作していない（テストのみ）。

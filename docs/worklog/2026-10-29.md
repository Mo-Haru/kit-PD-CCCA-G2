## 3. 実装

### 3-1. 無期限QRを「長期（最長3年）」に置き換え

- `mode: "unlimited"` を廃止し、`mode: "long"` を追加した。長期は期限が必須で、最長1096日（3年）。期限内なら何回でも閲覧できる。
- サーバーの設定は `QR_LONG_MAX_SECONDS`。作成時と期限変更時の両方で上限を確認する。期限切れの判定は、期限付きと長期で同じ処理にした。
- `/sharing` に「長期（最長3年、期限まで複数回閲覧可）」を追加した。選ぶと赤い注意書きを出し、期限の既定値を3年後にする。確認画面にも注意文を出す。
- 移行手順 `20261029_long_qr`：既存の `unlimited` は、作成から1096日後に切れる `long` に変わる。共有、版、閲覧セッションは残る。SQLite では表を作り直し、失敗したら元に戻して外部キーの設定も戻す。

### 3-2. 招待を「確認リンク・確認コード」で承認する流れに変更

1. 招待する人（A）が、リンクまたは QR で招待を作る（従来どおり）。
2. 招待を受けた人（B）が申請する。B の画面に、確認リンク（QR）と確認コード（例 `ABCD-EFGH`）が出る。
3. B は、それを A に直接渡す（対面や電話など）。
4. A は次のどちらかで家族登録する。どちらも、本人確認（再認証）が必要。
   - 確認リンク `/family/confirm` を開き、「パスキーで本人確認して家族に追加」を押す。
   - `/family` の招待一覧で確認コードを入力する。
5. コードを5回続けて間違えると、その申請は無効になる。B は家族画面で確認コードを再発行できる（前のリンクとコードは無効）。

- 確認リンクとコードは、サーバーには SHA-256 でだけ保存する。招待一覧 API には出さない。確認リンクのトークンは URL の `#` 以降にだけ入れる。
- 招待した本人以外が確認リンクを開いても、招待があるかどうかは区別せず 404 を返す。
- 追加した API：`POST /api/v1/family/invitations/confirm-link`、`POST /api/v1/family/invitations/<id>/confirmation`（再発行）。`POST .../<id>/confirm` は `{ "code": ... }` が必須になった。
- 移行手順 `20261029_family_invite_confirmation`：`family_invitations` に確認用の列と一意索引を追加した。変更前に申請された招待は、再発行するまで承認できない（409 `confirmation_required`）。

### 3-3. メール招待の停止

- `kind: "email"` は 400 `invalid_invitation` を返す。`POST /api/v1/family/invitations/accept` は削除した。
- DB の照合値の列と、移行手順 `20261021_contact_hash_hmac` は残した。保存済みの照合値は削除していない。

# ダミー回答の保存・共有テスト

質問6問は `app/data/answer-demo.json`、画面は `/answers/demo` です。既存のパスキー認証・PRFによる解錠・ブラウザ暗号化・保存APIを使います。実在の個人情報は入力しないでください。

## 初回準備

開発DBの初期化が済んでいれば、質問の追加だけ実行します。

```sh
pipenv run python -m flask --app run seed-answer-demo
```

Windowsでは先頭を `py -3.14 -m pipenv` にします。新しい環境では、その前にREADMEの `init-db` を実行してください。質問IDは固定です。追加コマンドは既存の回答やアカウントを変更せず、同じIDの内容が違う場合は更新せず停止します。

## 保存と再読み込み

1. `/answers/demo` からログイン・新規登録します。
2. 戻った画面で「この画面で鍵を解除」を押します。PRF対応の登録済みパスキーが必要です。
3. 「サンプル回答を入れる」で6問に入力し、内容を書き換えて試します。
4. 「回答内容を確認する」→「暗号化してDBに保存」を押します。保存成功時だけ版番号が表示されます。
5. 再読み込みし、もう一度鍵を解除するとDBの回答を復号して表示できます。

未保存の入力はページ移動で消えます。「保存内容を読み直す（入力を置換）」は現在の入力をDBの内容に戻します。「入力をリセット」だけではDBを変更しません。その後に保存すると、テスト質問6問の回答を未回答に戻します。他の質問の回答は保持します。別画面から更新された場合は競合エラーとし、最新版への自動上書きはしません。

## 共有リンク

1. 保存後に `/sharing` を開き、その画面でも鍵を解除します。
2. 質問・章・全体の範囲を選びます。「全体」はテスト質問以外の有効な質問も対象です。
3. 緊急用（最初の閲覧のみ）か、期限付き（31日以内）を選びます。
4. 「共有する内容を確認」で対象の回答と期限を確認し、確認欄にチェックしてリンクを作成します。設定を変えると再確認が必要です。
5. リンクを別のブラウザなどで開き、「内容を開く」を押すと復号して表示します。開くだけでは閲覧を開始しません。
6. 送信者の発行済み一覧で「この共有を停止」を押すと、受信者は次の取得から閲覧できません。

リンクは作成直後の画面でのみ表示・コピーできます。QR画像の生成は未実装です。秘密鍵はURLのfragmentに置き、サーバーへ送りません。回答を保存し直しても発行済みリンクの内容は変わりません。更新した回答を渡すときは、内容を確認して新しくリンクを作成します。

## 家族共有

送信者・受信者それぞれのテストアカウントを用意します。別のブラウザやプロファイルを使うとセッションを分離できます。

1. 送信者が `/family` で解錠し、「リンクで招待する」で招待リンクを作ります。
2. 受信者がログイン後、そのリンクで参加を申請します。
3. 送信者が申請を確認して接続します。
4. 送信者が相手と範囲を選び、内容確認・確認欄へのチェック後に共有します。
5. 受信者が `/family` で解錠し、受信した共有を開きます。
6. 回答を保存し直すだけでは共有は変わりません。共有の更新を明示的に行うと新しい内容になります。停止・期限切れ・接続解除後は次の取得から配信されません。

## 自動検証

```sh
pipenv run python -m pytest -q
```

`tests/test_demo_persistence.py` は一時SQLiteファイルと模擬パスキーを使い、通常のJSクライアントと実際のFlask APIを通して、暗号化保存・既存回答の保持・再読み込み・競合拒否・家族共有と更新・リンク閲覧・一回性・期限・停止を検証します。HTTP本文と保存レコードに回答平文・PRF出力・保管用鍵が含まれないことも確認します。開発DBや実機のパスキーは使いません。実機のPRF対応と認証操作は、上の手順で別途確認してください。

# ダミー回答の保存・共有テスト

質問6問は `app/data/answer-demo.json`、画面は `/answers/demo` です。既存のパスキー認証・PRFによる解錠・ブラウザ暗号化・保存APIを使います。実在の個人情報は入力しないでください。

## 初回準備

開発DBの初期化が済んでいれば、質問の追加だけ実行します。

```sh
pipenv run python -m flask --app run seed-answer-demo
```

Windowsでは先頭を `py -3.14 -m pipenv` にします。新しい環境では、その前にREADMEの `init-db` を実行してください。質問IDは固定です。追加コマンドは既存の回答やアカウントを変更せず、同じIDの内容が違う場合は更新せず停止します。

## 保存と再読み込み

1. `/answers/demo` からログイン・新規登録します。
2. 戻った画面で「この画面で鍵を解除」を押します。PRF対応の登録済みパスキーが必要です。
3. 「サンプル回答を入れる」で6問に入力し、内容を書き換えて試します。
4. 「回答内容を確認する」→「暗号化してDBに保存」を押します。保存成功時だけ版番号が表示されます。
5. 再読み込みし、もう一度鍵を解除するとDBの回答を復号して表示できます。

未保存の入力はページ移動で消えます。「保存内容を読み直す（入力を置換）」は現在の入力をDBの内容に戻します。「入力をリセット」だけではDBを変更しません。その後に保存すると、テスト質問6問の回答を未回答に戻します。他の質問の回答は保持します。別画面から更新された場合は競合エラーとし、最新版への自動上書きはしません。

## 共有リンク

1. 保存後に `/sharing` を開きます。解除前は、共有範囲の各回答欄に、回答全体を暗号化したデータの一部を表示します。個別の質問ごとの暗号文ではありません。
2. 質問・章・全体の範囲を選びます。赤い「回答の暗号化を解除」で青い「解除済み」に変わると、実際の回答を確認できます。「全体」はテスト質問以外の有効な質問も対象です。
3. 緊急用（最初の閲覧のみ）、期限付き（31日以内）、長期（最長3年、期限まで複数回閲覧可）から選びます。長期を選ぶと強い注意書きを表示し、期限の既定値を3年後にします。期限のないリンクは作れません。
4. 「共有する内容を確認」で対象の回答と期限を確認し、確認欄にチェックしてリンクを作成します。設定を変えると再確認が必要です。
5. リンクを別のブラウザなどで開き、「内容を開く」を押すと復号して表示します。開くだけでは閲覧を開始しません。
6. 発行済みの共有は、有効なら緑、停止済み・期限切れ・使用済みなら薄いグレーで表示します。「開く」またはカード内のどこを押しても、モーダルで発行時点の回答を表示します。上下の赤い「共有停止」は確認後に停止し、キャンセルすれば停止しません。「閉じる」またはEscで閉じます。受信者は停止後の次の取得から閲覧できません。

リンクとQRコードは作成直後の画面でのみ表示・コピーできます。QRコードは、作成で返ったリンク（`url`）だけを、同梱のライブラリで端末の中だけで描きます（`app/static/js/watashi/qrShareView.mjs` の `renderQrCanvas()`）。リンクの秘密はURLのfragmentに置きます。発行者が後から内容を確認できるよう、復号用の控えを端末内で暗号化して保存します。秘密鍵を平文でサーバーへ送りません。旧形式の共有には控えがないため、内容を再表示できない旨を出します。回答を保存し直しても発行済みリンクの内容は変わりません。長期リンクでも1回の閲覧セッションは30分・無操作5分で終了しますが、期限内ならリンクを開き直せます。

## 家族共有

送信者・受信者それぞれのテストアカウントを用意します。別のブラウザやプロファイルを使うとセッションを分離できます。

1. 送信者が `/family` の家族のカードの右上の「家族の招待」を開いて、「リンクで招待」または「QRコードで招待」を選びます。作るときに、パスキーの本人確認を求められます（`/family` に「回答の暗号化を解除」のボタンはありません）。QR画像は端末内だけで生成します。
2. 受信者には専用の招待画面が開きます。未ログインならログイン画面へ進み、戻ってから「xxxでログイン中」を確認して「招待を承諾する」を押します。ログインだけでは自動承諾しません。
3. 承諾すると、受信者の画面に確認リンク（QR）と確認コードが出ます。受信者はそれを送信者に直接渡します。画面を閉じた場合は、受信者の `/family` の「確認コードを再発行」で出し直せます（前のものは無効）。
4. 送信者は確認リンクを開いて「パスキーで本人確認して家族に追加」を押すか、`/family` の招待一覧で確認コードを入力して「確認コードで家族に追加」を押します。表示名だけでは追加できません。コードを5回続けて間違えると申請は無効になります。家族一覧では、共有可能な家族をチェックマークで示します。
5. 送信者が `/family` の「共有を開始」を押すと、`/family/share` で次の順に進みます。①回答の暗号化を解除 → ②共有する内容（範囲）を選ぶ → ③共有する家族と期限を決める → ④相手・鍵・期限・回答を再確認して、確認欄にチェック → 「共有を確定」。再確認のあとに相手の鍵が変わった場合は、確定せずに③へ戻ります。共有できる家族がいないと、「共有を開始」は押せません。
6. 「自分が家族に共有したもの」と「家族から共有されたもの」は、「開く」またはカード全体からモーダルで回答を表示します。暗号化された回答を開くときに、その場でパスキーの本人確認を求めます（取り消すと表示せず、「パスキーで本人確認して表示」で続けられます）。有効は緑、停止済み・期限切れは薄いグレー、再共有が必要な場合は薄い黄色で示します。送信側は「期限を変更」で入力欄を開き、「変更を保存」で期限を更新できます。内容の更新は「内容を選び直して更新」から、共有の開始と同じ画面で（家族と期限の手順は省いて）行います。配信停止（赤）と閉じるは、モーダルの右上に並びます（下部のボタンはありません）。配信停止は確認後に実行します。回答は、質問ごとに1つの枠（質問の文と回答）で表示します。
7. 回答を保存し直すだけでは共有は変わりません。共有の更新を明示的に行うと新しい内容になります。停止・期限切れ・接続解除後は次の取得から配信されません。

## 自動検証

```sh
pipenv run python -m pytest -q
```

`tests/test_demo_persistence.py` は一時SQLiteファイルと模擬パスキーを使い、通常のJSクライアントと実際のFlask APIを通して、暗号化保存・既存回答の保持・再読み込み・競合拒否・家族共有と更新・リンク閲覧・一回性・期限・停止を検証します。HTTP本文と保存レコードに回答平文・PRF出力・保管用鍵が含まれないことも確認します。開発DBや実機のパスキーは使いません。実機のPRF対応と認証操作は、上の手順で別途確認してください。

既存DBでは `init-db` により、無期限リンクを長期リンク（作成から最長3年）へ置き換えるスキーマ更新と、招待の確認コード用の列の追加が行われます。既存の共有・暗号文・閲覧セッション・招待は保持します。`tests/test_qr_long.py` と `tests/test_family_confirmation.py` は、移行の保持・再実行・失敗時のロールバックと、確認コード・確認リンク・再発行・失敗回数の上限を検証します。
